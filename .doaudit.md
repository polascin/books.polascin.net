# Opakovaný komplexný audit pre books.polascin.net

## Cieľ

Vykonaj opakované behy hĺbkového komplexného auditu PHP aplikácie **books.polascin.net** podľa [`.audit.md`](.audit.md) (bezpečnostný audit OWASP, integrita PHP/HTML/CSS/JS kódu, databázová vrstva a `setup_db.php`, blokovanie chránených súborov cez `.htaccess`, SEO a štruktúrované dáta, responzívny dizajn, prístupnosť WCAG 2.1, GDPR / cookie consent a jazyková korektúra anglických textov) a dodržiavaj bezpečnostné pravidlá uvedené v `.audit.md`.

## Postup

1. Spusti audit podľa kontrolného zoznamu v [`.audit.md`](.audit.md).
2. Zaznamenaj všetky nálezy vrátane ich závažnosti (🔴/🟠/🟡/🟢), príčiny a odporúčanej opravy.
3. Implementuj opravy a vylepšenia nájdené v aktuálnom kole.
4. Over zmeny relevantnými projektovými kontrolami:
   - PHP syntax lint: `php -l <file.php>` pre všetky zmenené PHP súbory
   - Databázová inicializácia: `php setup_db.php` (pri zmene schémy; len CLI, z webu je súbor blokovaný)
   - Tailwind build: `npm ci && npm run build:css`, potom `git diff --quiet -- assets/css/tailwind.css` — commitnutý bundle nesmie byť zastaraný (rovnakú kontrolu robí `deploy.yml` a pri drifte zlyhá). Vždy `npm ci`, nie `npm install` — inak sa build prestane viazať na `package-lock.json`
   - JS kontrola: `node --check assets/js/script.js` (a ostatné súbory v `assets/js/`)
   - Formátovanie a linting: `npx prettier --check assets/css/style.css assets/js/script.js .audit.md .doaudit.md README.md DEPLOY.md` (generované `assets/css/tailwind.css` a `assets/css/fonts.css` sa neformátujú)
   - PHP kvalita: `.\tools\quality.ps1` (PHPStan + PHP-CS-Fixer; opravy formátovania cez `.\tools\quality.ps1 -Fix`). PHAR nástroje najprv stiahne `.\tools\install-dev-tools.ps1` — pozor, ten zároveň **prepíše `phpstan-baseline.neon`** a tým zamaskuje nové nálezy; pri audite spúšťaj analýzu proti existujúcemu baseline
   - Trunk (ak je dostupný a `.trunk/trunk.yaml` je zavedený): `trunk check --all --no-progress`
   - Manuálna kontrola HTTP hlavičiek: `curl -I https://books.polascin.net/` — okrem `X-Frame-Options`, `X-Content-Type-Options`, HSTS, `Referrer-Policy`, `Permissions-Policy` a `Cross-Origin-Opener-Policy` musí byť prítomná aj `Content-Security-Policy` bez `'unsafe-inline'`
   - Konzola prehliadača na `/`, `/catalog.php` a `/about.php` — CSP nesmie hlásiť žiadne zablokované zdroje
   - Overenie blokovania chránených ciest: `curl -I https://books.polascin.net/setup_db.php`, `.../includes/functions.php`, `.../data/books.json`, `.../.env`, `.../.audit.md` — žiadna nesmie vrátiť 200 (očakávané 403 z `.htaccess`, prípadne 404 pri súboroch, ktoré `.deployignore` na server vôbec nenahrá)
   - Funkčné testy katalógu (`catalog.php` — vyhľadávanie a filtrácia podľa kategórie), cookie bannera a externých odkazov na knihy
5. Zapíš výsledky, vyriešené nálezy a poznatky pre ďalšie behy do [`.audit.md`](.audit.md) (ako nový „Beh #X" s odvolávkami na opravené súbory).
6. Opakuj kroky 1 až 5, kým audit nebude nachádzať žiadne nové bezpečne opraviteľné chyby alebo bugy.

## Bezpečnostné pravidlá

- Nevykonávaj nebezpečné alebo nekompatibilné automatické opravy, napríklad `npm audit fix --force`, bez samostatného posúdenia ich dopadov.
- Tailwind je zámerne pripnutý na verziu **3.4.17** — neaktualizuj ho na v4 v rámci auditu; zmenil by predvolené farby okrajov, škálu `shadow`/`rounded` a šírky ringov, čo by ticho prekreslilo celý web.
- Známe výnimky a nálezy, ktoré nie je možné bezpečne opraviť, zdokumentuj spolu s odporúčaným ďalším postupom.
- Pri bezpečnostných nálezoch uprednostni obranné riešenia a minimalizuj riziko regresie (bezpečnostné hlavičky v `.htaccess`, PDO prepared statements, `esc_html()`/`safeUrl()` escapovanie, CLI guard v `setup_db.php`, blokovanie `includes/`, `data/` a `.env`).
- Prihlasovacie údaje zo `.env` nikdy nevypisuj — over len prítomnosť a štruktúru kľúčov oproti `.env.example`.
- Ak sa zmeny týkajú `.htaccess`, cookie bannera, `setup_db.php`, databázovej schémy alebo JSON-LD schém, otestuj ich aj manuálne v prehliadači.

## Dokončenie

Po úspešnom ukončení všetkých auditných kôl **vždy** (bez ďalšieho pýtania sa):

1. Skontroluj finálny diff a stav repozitára (`git status`, `git diff --stat`).
2. Uisti sa, že všetky PHP súbory prechádzajú `php -l`, JS prechádza `node --check`, CSS/JS/Markdown sú zformátované a `assets/css/tailwind.css` zodpovedá zdrojom.
3. Over, že `.env` ani iné tajomstvá nie sú v stagingu ani v histórii (`git log --all -- .env`); lokálne hooks (`hooks/pre-commit`, `hooks/pre-push`) a workflow `secret-scan.yml` musia prejsť.
4. **Commitni** všetky relevantné zmeny auditu s výstižnou správou (vrátane zápisu „Beh #X" v [`.audit.md`](.audit.md)).
5. **Pushni na `main`:** `git push origin main` (bežný push, nikdy `--force` na `main`). Ak lokálny `post-commit` hook už pushol a nasadil, over `git status -sb`, že `main` nie je ahead of `origin/main`.
6. **Verifikuj nasadenie na produkcii** a výsledok zapíš do záznamu behu v [`.audit.md`](.audit.md):
   - HTTP 200: `/`, `/catalog.php`, `/about.php`, `/privacy.php`, `/terms.php` (smoke test z `deploy.yml` pokrýva `/`, `/privacy.php`, `/terms.php`)
   - Bezpečnostné hlavičky na `/` vrátane `Content-Security-Policy` **bez** `'unsafe-inline'`
   - Blokované cesty (nie 200): `/setup_db.php`, `/includes/functions.php`, `/data/books.json`, `/.env`, `/.audit.md`
   - Ak audit menil UI/aktíva: prítomnosť verziovaných `?v=` odkazov / očakávaných HTML markerov na produkcii
   - Ak beží GitHub Actions deploy: skontroluj posledný beh (`gh run list --workflow=deploy.yml --limit 1`); job `validate` musí byť zelený; job `deploy` môže byť skipped, kým nie sú `DEPLOY_*` secrets — vtedy je primárne nasadenie lokálny post-commit hook (pozri [DEPLOY.md](DEPLOY.md))
